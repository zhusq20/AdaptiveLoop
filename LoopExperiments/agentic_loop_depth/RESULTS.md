# 按分支分配 loop 的受控实验（CUDA 0，2026-11-12）

**结论。** 在原有 two-worker 算术任务与固定 few-shot 提示下，按第 2/3 轮数字 logit margin 决定是否继续计算，能把测试请求的平均延迟从固定 3 轮的 116.0 ms 降到 95.1 ms，同时在这组测试中保持 100% 整题正确率。但只换 four-shot 示例、保持阈值不变时，动态策略每组都错 1/270 个未见分支程序，固定 3 轮仍全对。因此这是一个任务内的平均延迟收益，尚不是跨提示稳定的无损提前退出。

本实验沿用 [`early_merge`](../early_merge/RESULTS.md) 的 Ouro-2.6B、两条各含两步算术的独立分支，以及一个只接受两路数字结果和最终加减号的汇总端。分工由实验给定；没有让 main agent 自己拆题、调用工具或生成 subagent 指令。因此它验证的是 **并行 worker 的 loop 深度调度**，不是完整 agentic workflow。

## 校准与未见程序评估

810 个不同的合法两步程序中，540 个用于设定退出阈值，270 个保留作测试。第 2、3 轮各用数字 logits 的前两名差值作置信度；阈值设为刚高于校准集中该轮所有错误答案的最大差值，分别为 1.5543 和 0.2333。未达到阈值则继续下一轮，最深第 4 轮。阈值只由校准程序确定，没有使用测试标签。测试组合为 400 组反事实四元组，每组 3 条等结果路线；1,200 条基础样例复用那 270 个源程序，不是 1,200 个独立程序。

| 策略 | 未见分支程序正确率 | 1,200 条基础组合正确率 | 四种反事实都对 | 平均关键分支深度 | 两支均第 2 轮退出 |
|---|---:|---:|---:|---:|---:|
| 固定 2 轮 | 95.56% | 92.83% | 85.08% | 2.000 | 100% |
| 固定 3 轮 | 100% | 100% | 100% | 3.000 | 0% |
| 固定 4 轮 | 100% | 100% | 100% | 4.000 | 0% |
| 动态 2/3/4 轮 | 100% | 100% | 100% | 2.263 | 73.67% |

动态策略在 270 个测试程序中让 226 个于第 2 轮退出、44 个于第 3 轮退出，没有使用第 4 轮。组合正确率由分支输出数字精确计算；原实验已验证汇总端在全部 110 个合法数字/运算组合上 100% 正确。完整计数见 [`analysis.json`](runs/ops2_2718/analysis.json)。

## CUDA 0 实际延迟

从 1,200 条基础组合中随机抽取 96 条；每条交替随机运行五种策略。两路 worker 在同一张 GPU 上以 batch=2 运行，汇总端再执行 1 轮。包含第 2/3 轮读出、CPU 分支决策、继续计算、GPU 同步和最终汇总；预先准备输入 embedding，不含 CPU 分词、网络、真实 subagent 工具调用。

| 策略 | 96 条实际正确率 | 平均延迟 | 中位延迟 | p90 延迟 | 平均 worker loop 总数 |
|---|---:|---:|---:|---:|---:|
| 固定 2 轮 | 90.63% | 87.6 ms | 87.0 ms | 89.9 ms | 4.000 |
| 固定 3 轮 | 100% | 116.0 ms | 115.2 ms | 119.0 ms | 6.000 |
| 固定 4 轮 | 100% | 144.4 ms | 143.7 ms | 147.5 ms | 8.000 |
| 动态、两支一起加深 | 100% | 95.4 ms | 87.9 ms | 117.0 ms | 4.521 |
| 动态、只加深不确定分支 | 100% | 95.1 ms | 87.5 ms | 116.3 ms | 4.281 |

只加深不确定分支相对固定 3 轮，配对平均快 20.93 ms，96 请求 bootstrap 95% 区间 [18.32, 23.36] ms；相对固定 4 轮快 49.37 ms，[46.79, 51.83] ms。只加深一支比两支一起加深少约 5.3% 的 worker loop 计算，但平均延迟差只有 0.34 ms，配对区间 [−0.06, 0.78] ms。这个区别符合关键路径直觉：只要有一支还要继续，同一请求仍须等待第 3 轮；减少非关键分支计算更多影响总 FLOPs，而不是响应时间。动态策略的 p90 也接近固定 3 轮。原始逐请求计时、抽样题目和协议见 [`latency.json`](runs/ops2_2718/latency.json)。

## 提示词稳健性

保持程序、标签、阈值和汇总端不变，只用两个新随机种子替换 worker 提示中的四道 few-shot 示例。两个新提示下，固定 3/4 轮均为 270/270 个未见程序正确；动态策略各为 269/270，1,200 条基础组合各为 99.67%。两次出错的都是同一测试程序 `2 + 5 + 2 = 9`：第 2 轮错答 `7`，却给出高于原阈值的 margin（2.42 与 1.67）；第 3 轮均改正。原提示下它也在第 2 轮错答 `7`，但 margin 仅 0.43，因而被正确地继续计算。详情及每轮预测见 [`robustness.json`](runs/ops2_2718/robustness.json)。这说明单一提示校准出的 logit margin 不足以作为可靠的跨提示退出证书。

## 对 agentic orchestration 的含义与限制

这次实验支持“同一任务中，动态 loop 深度可改善平均延迟与正确率的折中”；也表明单独给非关键 worker 省 loop 未必缩短关键路径。下一步若转向 main/subagent，应先测真实派工任务中的决策稳定性、调用与工具时间，以及全 workflow 的端到端延迟。当前几十毫秒的模型收益不能外推为多秒 agent 流程的同百分比收益。跨提示的高置信错误和 Ouro 多 token 生成时的 KV-cache 处理也是必须解决的工程边界。
